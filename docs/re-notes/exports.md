# XBDM export table

Stock XBDM 2.0.21256.0 (`xbdm.xex`, base `0x91f00000`). Titles and system modules import `xbdm.xex` by ordinal only; the image carries no export names.

## Declaration

The XEX security info field `export_table` (security info offset `0x160`) holds `0x91f95794`. The table is in `.text`; the PE `.edata` section of the basefile is zero-filled. Layout, big-endian:

```text
+0x00 u32[3] magic       0x48000000 0x00485645 0x48000000
+0x0c u32[2] module id   0x0000eceb 0x00008109   (library id 0xeceb8109)
+0x14 u32[3] version     0x00530800 0x00074500 0x00002020   (2.0.21256.0, 2.0.1861.0)
+0x20 u32    image base  0x000091f0   (base >> 16)
+0x24 u32    count       0x175 (373)
+0x28 u32    base        1 (first ordinal)
+0x2c u32[count] address offsets from 0x91f00000; 0 = unused ordinal
```

The hypervisor checks `(word3 << 16) | word4` against the import library id of each importer. The version words hold the low 24 bits of the module version and of the oldest compatible version (2.0.1861.0, the same value importers record as their minimum), then both top bytes (`major << 4 | minor`) in the third word; which byte of `0x2020` belongs to which version is not determinable from this image or the 2.0.16547 kernel export table (both have 2.0 in each), and xex-link writes the module version in bits 8-15. 373 ordinal slots exist: 253 are populated (251 distinct addresses), 120 are zero. All populated entries are code in `.text`; there are no data exports. Ordinals 3, 55, 57, 124 share one address; ordinals 4 and 5 share another.

Binary Ninja names follow `xbdm_export_<ordinal>_<description>`; a shared address uses its lowest ordinal. Behavior text is derived from HLIL. Binary Ninja does not decode `mtmsrd`, so HLIL stops at the first interrupt-disabled interlocked sequence; the rows for 46, 74, 78, 144, 147, 148, 193, 307, 308, 312, 345, 346, 361, 362, 363 were checked against the raw disassembly instead.

## openxbdm

The module's xex-link manifest (`xbox360/xex.toml`, `[exports]` with `module = "xbdm.xex"` and `min_version = "2.0.1861.0"`) makes xex-link build the table above from the `.xexports` records of the ELF (one per `export!`/`export_raw!` declaration; the macros are defined in `openxbdm/server/xbox360/src/exports.rs` and used by the domain backends under `src/backend/`, `src/exports/generic.rs`, and `src/lockfree/`) and append it after the IAT in an executable section. The hypervisor reads the table only from protected (code) pages; a table in data pages fails every import with `C0000156` (acceleration `doc/re-notes/xex-loader.md`). The slot count is the highest implemented ordinal; unimplemented ordinals are 0.

Importers use the console ABI: 64-bit registers, r14-r31 preserved in full, one register per 64-bit argument or result, 8-byte argument home slots at the caller's `sp+0x10 + 8*i` (the ninth argument's low word at `sp+0x54`). `export!` enters through `export_bridge`, which preserves the full nonvolatile registers around a 32-bit `extern "C" fn` with at most eight 32-bit arguments. Exports with 64-bit arguments or results, more than eight arguments, or variadic arguments adapt the convention in a naked entry declared with `export_raw!`.
